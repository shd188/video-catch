# GPL-3.0 合规说明

本文档说明本仓库（基于 [Cat-Catch](https://github.com/xifangczy/cat-catch) 的渠道分发形态）如何满足 **GNU GPL v3** 要求，以及付费「服务」与「软件」的边界。本文档不构成法律意见；正式商用前请咨询律师。

## 1. 许可关系

| 组件 | 许可 |
|------|------|
| 上游 Cat-Catch 2.x | GPL-3.0 |
| 本仓库对上游的修改、`channels/` 配置、`scripts/` 构建脚本 | GPL-3.0（与扩展一并分发时） |
| 你单独部署且**不随扩展分发**的订阅/激活 API 服务端 | 可专有（见第 5 节） |

收到本扩展或其构建产物的任何人，依法享有 GPL 第三条赋予的权利：运行、研究、修改、再分发（包括收费再分发）。

## 2. 分发扩展时你必须提供的内容

每次向客户交付 **`.crx` / `.zip` / 解压目录** 时，应同时满足：

1. **完整对应源码（Corresponding Source）**  
   - 与交付版本一致的 Git 标签或 commit（例如 `xiaoetong-v1.0.0`）。  
   - 公开仓库 URL，或随交付附 `source.zip`，或书面提供源码获取方式（GPL 对书面要约有时效要求，**推荐公开 Git**）。

2. **许可证全文**  
   - 保留根目录 `LICENSE`（GPL-3.0 全文）。

3. **版权与归属**  
   - 保留 `NOTICE` 与上游版权声明。  
   - 修改过的文件建议在文件头或 `CHANGELOG` 中注明变更。

4. **构建说明**  
   - 如何安装依赖、如何执行 `npm run build -- xiaoetong`、如何在浏览器加载 `dist/xiaoetong/`。  
   - 见 [docs/BUILD.md](./BUILD.md)。

5. **不得附加与 GPL 冲突的条款**  
   - 禁止要求客户放弃再分发或修改权利。  
   - 禁止仅提供二进制而不提供源码。

## 3. 你可以合法收费的内容（服务）

以下属于**服务/商品**，可与 GPL 软件一并销售，但须在合同与页面上写清：

- 小鹅通等渠道的**规则维护**（白名单、正则、深度搜索策略更新）
- **安装与排错支持**（侧载、企业策略）
- **订阅制更新**（新 tag 构建包、变更说明）
- **工单 / SLA / 培训文档**
- **可选**：托管在服务器上的配置下发（见第 5 节）；客户仍可自行 fork 去掉联网部分

**收费对象建议表述为**：「技术支持与持续适配订阅」，而非「专有软件许可证」。

## 4. 渠道包（白名单）与 GPL

- 各渠道目录 `channels/<id>/channel.json` 为**源码的一部分**，须随仓库公开。  
- 构建产物 `dist/<id>/` 由脚本从源码生成；交付 `dist` 时，源码 commit 必须可对应。  
- 客户修改 `channel.json` 后自行构建，完全符合 GPL。  
- **不得**声称「仅允许在付费前提下使用 GPL 代码」；付费约束只能针对**你提供的服务**，不能否定 GPL 权利。

## 5. 可选订阅 API（服务端）

若将来增加「订阅校验 / 动态规则下发」：

| 部分 | 建议 |
|------|------|
| 扩展内的 API 客户端代码 | GPL，公开在仓库；文档说明如何禁用 |
| 仅部署在你服务器上的 API | 可不开源 |
| 订阅过期 | 停止下发**你的**远程配置；内置白名单构建版仍应能基本运行，或文档说明自行构建无订阅版 |

用户 fork 后删除 `channel-init.js` 中的远程逻辑或改 `channel.json` 后自行构建，属于 GPL 合法使用。

## 6. 发布检查清单

每次对外发布渠道版本前：

- [ ] Git 打 tag，与交付包一致  
- [ ] `NOTICE`、`LICENSE` 在交付包内  
- [ ] 公开仓库可访问，或已附源码包  
- [ ] `docs/BUILD.md` 中的构建步骤可复现  
- [ ] 合同/商品页写明：软件 GPL，付费项为服务  
- [ ] 未冒用上游「猫抓」官方名义（自有品牌与 upstream 区分）  
- [ ] 遵守上游与用户文档中的版权与 opt-out 政策；仅用于用户有权访问的内容
