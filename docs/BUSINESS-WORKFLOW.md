# 推荐商业模式（简化版）

## 你要的模式

| 事项 | 做法 |
|------|------|
| 扩展安装包 | **每个渠道只打一次包**，有 bug 再发新版本 |
| 卖给用户 | **一个订单 = 一个激活码**（预生成 1000 个也行） |
| 激活码规则 | **用一次就作废**，别人不能再抢用 |

不必「每下一单就重新 build + 上传 zip」。

---

## 一次性操作（每个渠道）

### 1. 发布渠道包（后台 →「发布渠道包」）

本机：

```bash
npm run build -- xiaoetong
cd dist/xiaoetong && zip -r ../../releases/xiaoetong-2.6.9.zip .
```

后台上传 zip，版本号填 `2.6.9`。  
以后只有修复/升级时才再传 **2.7.0** 等新版本。

### 2. 生成激活码（后台 →「生成激活码」）

- 选择渠道（如 `xiaoetong`）
- 页面会显示该渠道**未使用**码还剩多少；少于 100 时会提示补货
- 填写数量（如 `1000`，也可点快捷 500/1000/2000）
- 点 **生成并下载 CSV** → 保存 CSV，相当于「卡库存」
- 码快用完时：在同一页再选渠道和数量，**重新生成一批**即可（旧码仍有效，新码追加进库存）

---

## 每单发货（30 秒）

1. 从 CSV 里取 **一行未发出的码**（或在后台「激活码查询」看未使用）
2. 发给客户：激活码 + 安装说明（侧载 `dist/xiaoetong` 或你提供的 zip 链接）
3. 客户在安装页输入激活码 → 该码变为 **已使用**，无法再给第二人

**不需要**再打包、不需要再上传服务器。

---

## 有新版扩展时

1. 本机 `npm run build` 打新 zip  
2. 后台「发布渠道包」上传一次  
3. **已激活用户**扩展里会提示更新下载（激活状态不变）  
4. **激活码库存不变**，未发出的码继续发新客

---

## 技术说明

- `single_use=1`：全球仅允许第一次激活成功；同一用户重装可继续校验（同一 `installation_id`）
- 批量接口：`POST /api/admin/licenses/bulk`，最多 10000 条/次
